# Trola.si Cleanup & Modernisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a test safety net under the app, upgrade it to a supported stack, fix the known bugs and remove the vibe-coded cruft, with no user-visible behaviour change except the bug fixes.

**Architecture:** Thin controllers split by concern (`StationController`, `SearchController`, `PageController`). LPP access stays in `LppApiService` (with a real cache in front of HTTP). Arrival formatting moves out of the `Station` model into `ArrivalsService`. Station lookup caching moves from the `CachesStations` trait into `StationRepository`. The nightly direction-pairing heuristic moves from the seeder into `SyncStations`, which computes everything in memory and writes it in one transaction. `StatsService` keeps its Redis key format, because production history depends on it.

**Tech Stack:** Laravel 13, PHP 8.4+, Pest 4, Larastan 3, Laravel Boost 2, MySQL 8, Redis (predis 3), Tailwind 4, Vite 8.

**Spec:** the maintenance review in the session of 2026-11-06 (summarised in the memory `trola-maintenance-state`) plus `CLAUDE.md`.

## Global Constraints

- Product principles from `CLAUDE.md`: fast, minimal UI, no tracking or ads. No new frontend frameworks.
- All user-facing copy stays in Slovenian. Do not change existing copy except where a task says so.
- Redis stats key formats are frozen: `stats_{Y_m_d}_{page}`, `stats_agg_{type}_{id}`, `stats_avg_dow_{n}`.
- URLs are frozen: `/`, `/search`, `/geosearch`, `/navodila`, `/stats`, `/{code}`, `/{code}/all`. Query params `q`, `direction` (`to|from|all`), `lat`, `lon` and `locationFailed` keep their meaning.
- Do not rename or delete migrations that already ran in production. In particular, `yyyy_mm_dd_add_fulltext_index_to_stations.php` stays as it is.
- The test suite never hits the live LPP API: `Http::preventStrayRequests()` is set globally.
- Pint (Laravel preset) runs on every PHP change. Commits contain no AI attribution.
- Work on branch `chore/cleanup`.

## Review Focus

1. **A station page during the nightly sync.** It must always show a direction and an opposite stop. The sync must never leave a window with null pairings. Covered by a test in Task 4.
2. **Search with MySQL boolean-mode operators** (`*`, `+`, `"`, `@`, `-`) or LIKE wildcards (`%`, `_`). This must return 200, not 500. Covered by a test in Task 6.
3. **A search query containing `&` or `#`.** The direction links must round-trip the query intact. Covered by a test in Task 6.
4. **`/geosearch` with missing, non-numeric or out-of-range `lat`/`lon`.** This redirects to `/search?locationFailed=1` and never returns 500. Covered by a test in Task 6.
5. **The LPP API down or returning non-2xx.** The station page still renders with no arrivals, and nothing broken gets cached. Covered by a test in Task 5.

### Task 4: Atomic station sync

**Files:**
- Create: `app/Actions/SyncStations.php`, `app/Console/Commands/SyncStationsCommand.php` (`stations:sync`).

**Interfaces (produced):**
- `StationRepository::findByCode(string $code): ?Station`, `findById(int $id): ?Station` and `forget(Station $station): void`. The cache keys are `station:code:{code}` and `station:id:{id}`, with a TTL of 86400 s. Only the selected columns are cached: `id, code, name, is_direction_to_center, opposite_station_id`.
- `SyncStations::__invoke(): SyncResult`, where `SyncResult` is a readonly class in the same file with `int $upserted, int $paired, int $unpaired`. It throws `RuntimeException` when the API returns null.

The pairing rules are unchanged:
1. Pair stations with the same name.
2. Pair the remaining stations with sequential codes, ±1, in ascending code order.
3. Direction: when exactly one code ends in `1`, that station is toward centre. Otherwise the lower code is toward centre.

The rules are computed in memory over the API payload. Then one DB transaction upserts every station with its final `opposite_station_id` and `is_direction_to_center`. After commit, the action calls `forget()` for every station.

### Task 6: Controllers, routes, input hardening

**Files:**
- Create: `app/Http/Controllers/StationController.php` (`show`, `showBothDirections`), `SearchController.php` (`search`, `geosearch`), `PageController.php` (`index`, `help`), `app/Http/Requests/GeosearchRequest.php`, `app/Support/FulltextQuery.php`.
- Modify: `app/Http/Controllers/Controller.php` (becomes an empty abstract base), `routes/web.php`, `resources/views/station-not-found.blade.php` (unchanged copy).

Route decisions:
- `/{code}` and `/{code}/all` get `->whereNumber('code')`. A non-numeric value falls through to the framework 404.
- A numeric but unknown code renders `station-not-found` with **status 404** and tracks `not_found`.
- Page views for `station_{code}` and `station_{code}_all` are tracked only after the station is found.
- Every route is named (`index`, `search`, `geosearch`, `help`, `stats`, `station`, `station.both-directions`), and hrefs are built with `route('search', ['q' => $q, 'direction' => 'to'])`.
- `StationController` builds the shared direction hrefs in one private method, `directionLinks(Station $station, ?Station $opposite): array{to:?string, from:?string, all:string}`.
- `GeosearchRequest` rules: `lat` and `lon` are `required|numeric`, with `lat` between 45 and 47 and `lon` between 13 and 16 (Slovenia with margin). On failure, redirect to `route('search', ['locationFailed' => 1])` and do not show an error bag. Override `failedValidation`.
- `FulltextQuery::booleanPrefix(string $input): ?string` strips `+-<>()~*"@` and trims. It returns null when the result is empty; otherwise it appends `*` to each whitespace-separated term. LIKE terms are escaped for `%`, `_` and `\`.
- `direction` outside `to|from|all` is treated as `all`.
